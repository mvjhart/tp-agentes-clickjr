# GitHub Issues — Planificación del proyecto

Este documento contiene los borradores de los Issues del proyecto **TP · Construcción 100 % agéntica — ClickJr**.

Su objetivo es trasladar la organización del trabajo acordada por el equipo a GitHub, conservando la distribución de tareas, sus entregables y los criterios de finalización.

## 1. Criterios de organización

- Se utilizarán cinco Issues principales, uno por cada agrupación de tareas de la distribución original.
- Cada tarea T1–T15 tendrá su propio Issue subordinado.
- Los Issues principales se identificarán con la etiqueta `tipo:epica`.
- Los Issues de tareas se identificarán con `tipo:tarea`.
- Las etiquetas de etapa permitirán filtrar las actividades por agrupación.
- Los responsables se asignarán cuando el equipo los acuerde. Los roles de coordinación no implican asignaciones automáticas.
- Las relaciones de dependencia se registrarán por separado de las relaciones padre-hijo.
- Las tareas podrán avanzar en paralelo siempre que sus dependencias lo permitan.

Los títulos conservan los identificadores T1–T15 de `docs/organizacion.md` para facilitar la trazabilidad.

# 4. Dependencias y trabajo en paralelo

Las siguientes relaciones son orientativas y deberán registrarse como dependencias únicamente cuando sean necesarias para comenzar una tarea.

| Tarea | Relación de trabajo |
|---|---|
| T1 | Preparación inicial del repositorio. |
| T2 | Puede avanzar en paralelo con T1. |
| T3 y T4 | Análisis independientes de R1 y R2. |
| T5 | Se apoya en T3. |
| T6 | Se apoya en T4. |
| T7 | Prepara la estructura general. |
| T8 | Requiere los materiales de T2 y la estructura de T7. |
| T9 | Se apoya en T5 y en la estructura de T7. |
| T10 | Se apoya en T6 y en la estructura de T7. |
| T11 | Puede avanzar mediante propuestas y acuerdos grupales en paralelo con el desarrollo. |
| T12 | Requiere versiones de los módulos que se van a integrar y los acuerdos técnicos y visuales aplicables. |
| T13 | Requiere una versión integrada de la landing. |
| T14 | Puede desarrollarse progresivamente y actualizarse hasta el cierre del proyecto. |
| T15 | Requiere la versión final revisada y la documentación correspondiente. |

La tabla no implica que todas las tareas deban esperar a que termine una etapa completa. Se priorizará el avance paralelo cuando no exista una dependencia real.

# 5. Criterios generales del proyecto

- El código debe construirse íntegramente mediante agentes de programación, sin edición manual.
- La landing presenta propuestas conceptuales: no debe ejecutar agentes, conectar APIs ni implementar automatizaciones reales.
- Las sentencias originales deben conservar su redacción exacta.
- Las decisiones adicionales de diseño deben distinguirse de las reglas originales.
- El logo original de ClickJr es obligatorio.
- Todos los integrantes deben interactuar con agentes, revisar resultados y participar en las decisiones.
- Los aportes individuales deben documentarse con evidencia y sin atribuciones anticipadas.
- Fecha de entrega: **26/11/2026**.
